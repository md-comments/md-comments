# Project Governance

This document outlines the governance model for the `md-comments` project.

## Governance Model

`md-comments` is an open-source project governed by a **Project Lead / Maintainer-driven** model. Since the project is currently in its early stages, decision-making is led by the project creator and lead maintainer.

As the project grows, we aim to transition to a more distributed consensus-based model involving a core team of maintainers.

## Roles

We define the following roles for contributors:

### Contributors

Contributors are community members who participate by:

- Submitting bug reports, feature requests, and feedback.
- Participating in discussions on issues, pull requests, or other channels.
- Submitting code changes via pull requests (bug fixes, features, documentation, tests).

### Maintainers

Maintainers are contributors who have demonstrated a long-term commitment to the project. They have write access to the repository and are responsible for:

- Reviewing and merging pull requests.
- Triage of issues and organizing milestones.
- Assisting in architectural decisions and code reviews.
- Helping contributors and enforcing the Code of Conduct.

### Project Lead

The Project Lead is responsible for the overall direction of the project, final architectural decisions, and release planning. The current Project Lead is:

- **Marat Strelets** (@mstrelex)

## Decision Making

Our goal is to reach consensus on all changes.

1. **Proposal**: Major changes should be proposed as issues or draft pull requests to discuss feasibility and design.
2. **Discussion**: Community members and maintainers review the proposal, offering feedback and suggestions.
3. **Consensus**: We aim for agreement among participating maintainers.
4. **Resolution**: If a consensus cannot be reached, the Project Lead makes the final decision.
