Architecture & Storage

Understand how Markdown Comments achieves complete SaaS-independence through Git custom references.

The Git-Native Storage Model

Traditional commenting tools either write HTML comments directly into markdown source files (causing diff noise and token bloat for LLMs) or store review comments in proprietary third-party databases.

Markdown Comments stores discussion threads inside a dedicated custom Git reference:

refs/md-comments/data

This isolates all comment data from your branch list (refs/heads/) and tags (refs/tags/), ensuring that commits, PRs, and CI pipelines remain completely clean.

Multi-Platform Synchronization

Because discussion data is stored in Git, comments sync transparently across all client interfaces:

  • Web Browsers: Via this Plain HTML embed or the Starlight Astro plugin.
  • VS Code / Cursor / Antigravity: Native extension with margin pins and hover cards.
  • Obsidian: Community plugin with live side panel discussion feeds.
  • GitHub Chrome Extension: Review comments overlaid directly on rendered GitHub markdown files.

Security & Permissions

Markdown Comments relies on GitHub's repository access control. Only users with repository write permissions can push commits to refs/md-comments/data, preventing unauthorized modifications.
